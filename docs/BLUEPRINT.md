# 首版实施蓝图

更新日期：2026-09-22。蓝图类型：`single-blueprint`。这是已确认范围的执行合同，不是实施完成报告。

产品与字段唯一依据：[总设计案](E:/PersonalAI/archived/SmallProjects/demon_lily_and_the_noir_maid/docs/DESIGN.md)。当前状态与证据唯一记录：[续接记录](E:/PersonalAI/archived/SmallProjects/demon_lily_and_the_noir_maid/docs/NEXT.md)。

## 1. 目标、交付与停止点

在真实 SillyTavern 中，以诺雅视角玩到一段可自由回应的宅邸与城市日常；同层 NVL 界面、人物状态、保存恢复及异常修复形成闭环。首个内容入口为“寻找两人共用的香气”，不强制走完整外出路径。

预期交付：可维护的角色卡与前端源文件、本地导入测试包、使用与恢复说明、自动检查和实际试玩证据。具体源目录、导出格式与素材数量在实施时按最小需要确定，不提前建立空壳。

首次试玩后，提供提出具体改进和再次试用的机会。用户提出改进时，在该次明确范围内修订并复测；若用户直接接受且必验项已通过，不人为制造修改来满足流程。完成后停在用户首版验收，不自动进入后续扩展或公开发布。

## 2. 执行边界

- 当前许可仅覆盖三份设计文档。P0～P5 的实现和运行操作尚未启动。
- 文档落盘后，用户明确要求按蓝图实施，才进入相应项目源码与本地自动测试工作。
- 安装或升级依赖、改全局规则、酒馆导入或设置、发送消息、付费或真实模型调用、Git 提交和推送、外部发布分别核对其实际操作范围；不由文档创建许可推导。
- 优先已安装的原生能力、普通数据结构和小型校验逻辑。不为单卡建立通用数据库、状态框架或第二套聊天系统。
- 最大蓝图深度 1，子蓝图 0，`runtimePersistentBlueprintBudget = 0`。
- 一次只激活一个阶段。真实失败可开启一条单层、非持久的临时问题支线，写明触发证据、父阶段和返回点；解决或明确阻塞后回到父阶段。不凭“还可更细”增加蓝图或交付分母。
- 产品范围、宿主形态或状态权威发生实质改变时，提出变更，不静默改写总设计。

## 3. 阶段合同

### P0 · 固定制作基线

- **输入：**总设计、原作对照、前序接口核对、用户截图及本地宿主信息。
- **输出：**最小字段与输出格式合同、来源分层、依赖和素材缺口。写进现有文档相应章节；仅在实际使用需要时增设维护材料。
- **允许范围：**已获准实施后，整理本项目资料、定义最小机器格式与样例；先只读复查实际依赖。
- **边界：**不把译文错配升级成原作事实；不自动复制或分发游戏素材；不把未确认的图像或框架锁成依赖。
- **退出条件：**字段、初始值、范围、写入者、读取者明确；正文与变化清单可确定性分离；空清单与缺失清单可区分；数值到达边界的处理有例子；素材缺口、使用门与依赖版本可追踪。
- **证据：**来源定位、字段合同和最小格式样例检查。仅证明基线明确，不证明运行成功。
- **失败处理：**保留有证据的基线，对真正影响实现的缺项逐项处理，不补造原作事实。
- **下一道门：**进入 P1；涉及宿主写操作或模型调用时先明确测试范围。

### P1 · 最小真实酒馆闭环

- **输入：**P0 合同、实际宿主能力、经允许的专用测试聊天或测试卡。
- **输出：**朴素界面下的一条真实输入、回复、最小状态样本与恢复链路。
- **允许范围：**最小消息桥接和卡片专属状态逻辑；本地测试。宿主操作仅在已明确测试对象和范围内执行，保留用户已有聊天。
- **边界：**不制作完整视觉、不铺全部人物字段、不依赖伪聊天绕过真实链路；不以隐藏上下文的消息标志单纯隐藏界面。
- **退出条件：**输入进入真实聊天；下一次生成实际收到有效状态；选中回复与其快照一致；刷新后数据仍在；重复通知不重复结算。
- **证据：**本地最小回归检查、真实宿主的操作记录与保存恢复结果；提示拼装证据和实际模型生成证据分别标注。
- **失败处理：**锁定接口、时序或保存问题，留在 P1 修复；不靠视觉工作绕开失败。
- **下一道门：**P1 通过后进入 P2；调用范围仍有缺口时只交付已取得的部分证据。

### P2 · 桌面与手机 NVL 原型

- **输入：**通过 P1 的消息链路、用户视觉参考、可用的测试素材。
- **输出：**场景背景、正文、独立人物栏、输入区、前后轮与历史导航的双端原型。
- **允许范围：**布局、基础样式和必要交互；明确标记测试素材用途。
- **边界：**不把故事拆成强制点击片段；不把手机做成缩小桌面；不使用持续动画代替信息层级。
- **退出条件：**长文可读，人物栏与正文分离，草稿和阅读位置稳定，手机软键盘不破坏核心操作；用户确认布局。
- **证据：**桌面和窄屏截图、实际操作记录、焦点和减少动效检查；窄屏模拟与真实手机证据分别记录。
- **失败处理：**修正当前版式或接入边界，保留 P1 有效链路。
- **下一道门：**用户确认阅读布局后进入 P3，不由截图检查代替其选择。

### P3 · 完整状态、颜色与异常恢复

- **输入：**总设计第 6、7 节，P1 链路与 P2 布局。
- **输出：**全部人物字段、叙事状态、头像、有效颜色表现、整轮结算与修复入口。
- **允许范围：**卡片专属校验、计算、保存与渲染；最小必要的状态诊断和清单修复。
- **边界：**无莉莉希雅好感度替代；不把修复入口扩成通用后台；不在后台额外调用模型；保留其他脚本命名空间。
- **退出条件：**字段和范围与总设计一致；空清单、重生成、分支、重复事件、历史修订、切换聊天均正确处理；异常暂停与修复恢复完整；颜色只跟随有效状态。
- **证据：**一组最小可重复的本地回归检查，加真实宿主的异常、修复、保存与分支记录。
- **失败处理：**保留最后有效状态、正文和草稿，停在待同步；修复后从正确基线重算。
- **下一道门：**状态合同通过后进入 P4。

### P4 · 首段内容与最小设定接入

- **输入：**原作依据、用户确定的续篇关系与起点、通过 P3 的数据和界面。
- **输出：**人物行为规则、必要世界设定、共用香气开场与自然日常推进。
- **允许范围：**首版实际需要的角色卡文本、世界设定与场景内容；原作事实、人物观点和同人扩展分层。
- **边界：**不塞入整部翻译对照；不强制外出、购买或成长；不替玩家决定诺雅的行动；不扩建街道百科。
- **退出条件：**接受、推迟或改变邀请都能继续；莉莉希雅主动而不夺取玩家决定；城市通过生活细节呈现；数值变化有对应经历。
- **证据：**三类选择的实际样本、状态依据检查、用户对关系基调与城市氛围的反馈。
- **失败处理：**修正提示或场景组织，保持数值和宿主合同，不用加系统掩盖内容失真。
- **下一道门：**进入 P5 集成试玩。

### P5 · 真机试玩、修订与首版验收

- **输入：**P1～P4 的实现、素材资格记录、全部已取得证据。
- **输出：**本地导入测试包、使用和恢复说明、验收记录；用户提出改进时，另包含一次针对性修订及复测。
- **允许范围：**首版缺陷修复、已确认的试玩改进、本地打包；真实导入使用明确允许的测试对象。
- **边界：**保留原聊天与原件；无自动发布、Git 提交或后续系统扩展；发布用途素材单独核对。
- **退出条件：**第 4 节场景逐项有结果，未通过项公开；用户实际体验并明确接受首版。自动化不代填用户验收。
- **证据：**自动检查、静态视觉、真实酒馆与手机、用户反馈分别记录。
- **失败处理：**回到对应阶段修复并重跑受影响场景，保持同一蓝图；真实设备或调用范围缺失时保留明确的未验门。
- **下一道门：**停在本次首版验收；后续更新与公开发布另定。

## 5. 证据分类与执行规约

- **automated：**字段、格式、计算、分支及去重等可重复检查。优先一组小型可运行测试，不先引入测试框架。
- **static-preview：**文档、打包结构、离线界面和截图。与运行结果分开。
- **real-host：**真实酒馆输入、生成、保存、重开、异常恢复与设备行为。源码存在接口不等于运行通过。
- **driver：**用户确认设计、布局与最终体验。三者分别记录，设计确认不等于产品验收。

测试先覆盖本阶段改变的行为，再运行项目实际具有的类型检查、静态分析、构建或集成检查。没有对应工具时记录不适用，不编造通过记录。

每个阶段结束后只在续接记录更新当前事实、证据与下一步；本文件保留执行合同。只有范围或标准发生明确变更时才更新合同。
