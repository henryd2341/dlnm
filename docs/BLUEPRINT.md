## 1. 目标、交付与停止点

在真实 SillyTavern 中，以诺雅视角玩到一段可自由回应的宅邸与城市日常；同层 NVL 界面、人物状态、保存恢复及异常修复形成闭环。首个内容入口为“寻找两人共用的香气”，不强制走完整外出路径。

预期交付：可维护的角色卡与前端源文件、内容哈希隔离的本地开发资源、可导入角色卡、同名使用说明和归档包。每个已获准阶段先完成构建与打包，再交用户手动检查；自动检查、真实宿主和实际试玩只在当轮另有许可时执行并分别留证。

首次试玩后，提供提出具体改进和再次试用的机会。用户提出改进时，在该次明确范围内修订并复测；若用户直接接受且必验项已通过，不人为制造修改来满足流程。完成后停在用户首版验收，不自动进入后续扩展或公开发布。

- 优先已安装的原生能力、普通数据结构和小型校验逻辑。不为单卡建立通用数据库、状态框架或第二套聊天系统。

- 最大蓝图深度 1，子蓝图 0，`runtimePersistentBlueprintBudget = 0`。
- 一次只激活一个阶段。真实失败可开启一条单层、非持久的临时问题支线，写明触发证据、父阶段和返回点；解决或明确阻塞后回到父阶段。不凭“还可更细”增加蓝图或交付分母。

## 3. 阶段合同

### P0 · 固定制作基线

- **输入：**总设计、原作对照、前序接口核对、用户截图及本地宿主信息。
- **输出：**字段基线、实际版本对应的 MVU Zod Schema/初始化/输出格式约定、世界书与正则职责、来源分层及依赖/素材缺口。写进现有文档，不增加蓝图。
- **允许范围：**已获准实施后，整理本项目资料、定义最小机器格式与样例；先只读复查实际依赖。
- **边界：**不把译文错配升级成原作事实；不自动复制或分发游戏素材；不把未确认的图像或框架锁成依赖。
- **退出条件：**字段、初始值、范围、MVU 写入链和前端读取者明确；已核实 MVU Zod 配套协议与 Schema 接入；世界书和正则职责明确；空更新/缺失及数值边界有配套样例；素材缺口、使用门与实际依赖版本可追踪。旧自定义协议检查不计入新路线通过。
- **证据：**来源定位、字段合同和最小格式样例检查。仅证明基线明确，不证明运行成功。
- **失败处理：**保留有证据的基线，对真正影响实现的缺项逐项处理，不补造原作事实。
- **下一道门：**进入 P1；涉及宿主写操作或模型调用时先明确测试范围。

### P1 · MVU Zod 与卡片组件接入

- **输入：**P0 合同、实际宿主能力、经允许的专用测试聊天或测试卡。
- **输出：**具备实际世界书/正则绑定、MVU Zod Schema/初始化及前端读取入口的最小卡片组件组合。
- **允许范围：**本卡组件、最小 Schema 接入和必要样例检查。宿主操作限于获准测试对象；复用现有 MVU 能力，不自建原生变量系统。
- **边界：**不制作完整视觉、不提前扩展全部剧情，不以只有 description/脚本的空壳卡代替上下文接入，也不单独测试酒馆生成。
- **退出条件：**世界书实际绑定且必要条目参与上下文拼装；正则已绑定/启用且显示与提示处理范围正确；MVU Zod 初始化/样例更新有效，前端读取入口对应同一消息/分支的数据。无需为这一阶段单独调用模型来证明宿主能回复。
- **证据：**组件绑定检查、Schema/规则样例、上下文拼装中的本卡必要内容以及 MVU 状态读取对应。人工样例不标为模型生成，接口声明不标为实际启用。
- **失败处理：**只处理本卡绑定、Schema 或上下文接入的具体失败；旧原生变量探针不再修复或补测。
- **下一道门：**组件接入通过后进入 P2；完整的正文/状态/历史/保存对应在最终前端继续验收。

各项证据按来源记录于 NEXT；用户阶段接受和代理实际观察分开，不从一句验收反馈补造逐项宿主运行记录。

### P2 · 桌面与手机 NVL 原型

- **输入：**通过 P1 的 MVU Zod/世界书/正则组件接入、用户视觉参考、可用测试素材。
- **输出：**浏览器 Fullscreen API 承载的完整 NVL，带场景背景、自动更新的正文、四角人物栏、输入区、前后轮与历史导航；非全屏最终只保留扩宽“人物与状态”栏的轻前端，酒馆原生正文与输入继续可用。
- **允许范围：**使用 Vue 3 + TypeScript + Vite 实现布局、基础样式和必要交互；流式与非流式回复都自动回到同一真实消息/分支；正文采用“剥离技术块 → 宿主 Markdown → HTML 清理 → `v-html`”的共同显示管线，并允许仅含经校验 `color` 的 span。项目 `public` 图片只作开发占位，正式运行图片由用户自行安装 Illustration-Gremlin 并导入当前角色图包。
- **边界：**不把故事拆成强制点击片段；不把手机做成缩小桌面；不使用持续动画代替信息层级。
- **退出条件：**新开场自动读取实际保存的 MVU 初值，无需发送聊天消息或模型调用；流式正文随生成连续出现，非流式结束后自动回读，最终正文、人物栏与所选消息/分支一致。Markdown 与受限染色在实时/历史路径一致且清理边界有效。点击默认入口实际进入浏览器 Fullscreen API 全屏（不是网页覆盖层），返回/Escape 回到无场景图的轻前端；长文可读，草稿和阅读位置稳定，手机软键盘不破坏核心操作；用户确认布局。
- **证据：**当前先记录 Vite 构建与打包，交用户手验。类型检查、自动检查、桌面和窄屏预览、焦点与减少动效检查只在另获许可后执行；缺项明确标注。构建成功不代替酒馆实际呈现；窄屏模拟与真实手机证据分别记录。
- **失败处理：**修正当前版式或接入边界，保留 P1 有效链路。
- **下一道门：**用户确认阅读布局后进入 P3，不由截图检查代替其选择。

### P3 · 完整状态、颜色与异常恢复

- **输入：**总设计第 6、7 节，P1 的 MVU Zod 接入与 P2 布局。
- **输出：**全部人物字段、叙事状态、头像、有效颜色表现、整轮结算与修复入口。
- **允许范围：**本卡 Zod Schema、MVU 更新规则与前端映射；必要的异常提示和修复入口。优先复用 MVU 的解析、存储及事件能力，不另造平行状态权威。
- **边界：**无莉莉希雅好感度替代；不把修复入口扩成通用后台；不在后台额外调用模型；保留其他脚本命名空间。
- **退出条件：**字段和范围与总设计一致；空清单、重生成、分支、重复事件、历史修订、切换聊天均正确处理；异常暂停与修复恢复完整；颜色只跟随有效状态。
- **证据：**一组最小可重复的本地回归检查，加真实宿主的异常、修复、保存与分支记录。
- **失败处理：**保留最后有效状态、正文和草稿，停在待同步；修复后从正确基线重算。
- **下一道门：**状态合同通过后进入 P4。

### P4 · 首段内容与最小设定接入

- **输入：**原作依据、用户确定的续篇关系与起点、通过 P3 的数据和界面。
- **输出：**人物行为规则、人物索引、必要世界设定、地点检索条目、共用香气开场与自然日常推进；内容条目与技术条目分开维护。
- **允许范围：**首版实际需要的角色卡文本、世界设定与场景内容；原作事实、人物观点和同人扩展分层。
- **边界：**不塞入整部翻译对照；不强制外出、购买或成长；不替玩家决定诺雅的行动；不扩建街道百科。
- **退出条件：**接受、推迟或改变邀请都能继续；莉莉希雅主动而不夺取玩家决定；城市通过生活细节呈现；人物/地点查询命中对应的有来源条目，规范地点名与图片映射一致；数值变化有对应经历。缺图不限制叙事，未确认素材目录不生成角色身份。
- **证据：**三类选择的实际样本、状态依据检查、用户对关系基调与城市氛围的反馈。
- **失败处理：**修正提示或场景组织，保持数值和宿主合同，不用加系统掩盖内容失真。
- **下一道门：**进入 P5 集成试玩。

### P5 · 真机试玩、修订与首版验收

- **输入：**P1～P4 的实现、素材资格记录、全部已取得证据。
- **输出：**本地导入测试包、使用和恢复说明、验收记录；用户提出改进时，另包含一次针对性修订及复测。
- **允许范围：**首版缺陷修复、已确认的试玩改进、本地打包；真实导入使用明确允许的测试对象。
- **边界：**保留原聊天与原件；无自动发布、Git 提交或后续系统扩展；发布用途素材单独核对。
- **退出条件：**第 4 节场景逐项有结果，未通过项公开；用户实际体验并明确接受首版。自动化不代填用户验收。
- **证据：**自动检查、静态视觉、真实酒馆与手机、用户反馈分别记录。
- **失败处理：**回到对应阶段修复并重跑受影响场景，保持同一蓝图；真实设备或调用范围缺失时保留明确的未验门。
- **下一道门：**停在本次首版验收；后续更新与公开发布另定。

## 5. 证据分类与执行规约

- **automated：**字段、格式、计算、分支及去重等可重复检查。优先一组小型可运行测试，不先引入测试框架。
- **static-preview：**文档、打包结构、离线界面和截图。与运行结果分开。
- **real-host：**真实酒馆输入、生成、保存、重开、异常恢复与设备行为。源码存在接口不等于运行通过。
- **driver：**用户确认设计、布局与最终体验。三者分别记录，设计确认不等于产品验收。

验证只执行当轮明确允许的项目。当前阶段先构建并打包成品，自动测试、类型检查、lint、浏览器和真实宿主操作均不沿用旧许可；未执行项在 NEXT 明列，不用历史通过记录代替本轮结果。获得新的测试许可后，再从受影响行为的最小检查开始。

每个阶段结束后只在续接记录更新当前事实、证据与下一步；本文件保留执行合同。只有范围或标准发生明确变更时才更新合同。
